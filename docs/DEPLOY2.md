## 1. ★ 선행 — 전송량 (Render가 끊긴 진짜 원인)

Render Hobby 워크스페이스는 월 **5GB 아웃바운드**가 포함이고 초과하면 과금하거나 무료 서비스를 정지시킨다.
문제는 플랫폼이 아니라 우리 쪽이다.

`server/index.js:93`
```js
const io = new Server(http, { cors: { origin: '*' } });
```
**`perMessageDeflate`가 없다 → socket.io v4는 압축이 기본 꺼짐이다.** world·state가 생 JSON으로 나간다.
세이브 스냅샷이 게임당 1.6MB급이니 접속 한 번에 메가 단위가 흐른다. JSON은 8~10배 압축된다.

해야 할 것 셋:

1. `perMessageDeflate: { threshold: 1024 }` 를 켠다. (한 줄)
2. 정적 파일(1.6MB)을 GitHub Pages로 뺀다 → 서버 egress에서 통째로 빠진다.
3. 세션당 송신 바이트를 한 번 계측한다. 압축만으로 충분한지, 정말 옮겨야 하는지가 숫자로 갈린다.

> 계측은 `io.engine.on('connection', ...)` 에서 소켓별 누적 바이트를 세고 disconnect 때 한 줄 찍으면 된다.
> 이 수치는 나중에 DB 텔레메트리(§5-5)로 그대로 넘어간다.

## 2. 서버는 어디에

### 2-1. 조건부터

계정·DB를 붙이는 순간 조건이 하나 늘어난다. **영구 디스크**다.
세이브가 날아가면 방이 안 남고, SQLite 파일이 날아가면 계정이 통째로 사라진다.
Render 무료는 디스크가 휘발성이라 **이 시점부터 후보에서 빠진다**(데모용으로만 남긴다).

정리하면 필요한 건 넷이다: 영구 디스크 · 슬립 없는 상시 가동 · 넉넉한 아웃바운드 · 한국에서 쓸 만한 지연.

### 2-2. 후보 비교 (2026-08 기준)

### 2-3. 권하는 순서 — 검증 먼저, 절약 나중

마감이 걸린 상황에서 제일 위험한 건 "무료를 좇다가 이틀을 태우는 것"이다. 그래서 2단으로 간다.

**1단계 — Railway로 파이프라인을 먼저 세운다.**
신규 계정에 일회성 $5 크레딧이 있다. git push 배포에 볼륨 클릭 한 번이면 영구 디스크가 붙는다.
여기서 확인할 것은 호스팅이 아니라 **우리 구조**다. Pages↔서버 크로스 오리진이 뚫리는가, SQLite가 볼륨에서 도는가,
압축 후 전송량이 실제로 얼마인가. 이게 다 초록불이 되면 그 다음은 어디로 옮기든 같은 그림이다.

**2단계 — 굳은 뒤에 고른다.**
- 완전 무료로 끝까지 가겠다 → **Oracle Always Free(도쿄)**. 상시·무료·10TB, 유료 전환이 아예 불필요.
  세팅은 설치 스크립트와 단계별 명령으로 넘긴다(Caddy 자동 TLS + systemd + 방화벽까지).
  ★ 주의: 2026-06-15부터 무료 ARM 한도가 4 OCPU/24GB → **2 OCPU/12GB로 반토막**. 그래도 이 게임엔 차고 넘친다.
  ★ 주의: 가입 시 카드 인증이 필요하고, ARM 용량을 못 잡아 며칠 헤매는 경우가 있다. **그래서 1단계를 먼저 한다.**
- 손이 덜 가는 쪽이 낫다 → **Railway Hobby $5 유지**. 월 5천원대로 남은 기간의 삽질을 산다.
- 한국 지연이 최우선이면 → **Lightsail 서울**. 다만 VM 세팅 부담은 Oracle과 같다.

**심사 기간 대비**: 어느 쪽을 고르든 Pages의 서버 주소는 한 줄이다(§4-2). 주소만 바꾸면 5분 안에 갈아탈 수 있으니,
심사 직전에 두 곳을 동시에 띄워 두고 하나가 죽으면 즉시 넘기는 이중화가 가능하다.

## 3. DB는 어디에

### 3-1. SQLite 파일 하나. 별도 DB 서비스는 두지 않는다.

관리형 Postgres(Neon·Supabase 무료 티어)를 붙이지 않는 이유는 셋이다.
쿼리마다 네트워크 왕복이 붙고, 무료 티어는 놀면 잠들어 첫 접속을 또 느리게 만들고,
정작 우리가 넣을 데이터가 **계정 몇 줄과 방 목록 몇 줄**이라 그 대가를 치를 이유가 없다.

디스크에 파일 하나 두면 왕복이 0이고, 백업은 복사 한 번이고, 비용이 0이다.

### 3-2. ★ `node:sqlite` — 의존성을 추가하지 않아도 된다

**Node 22에 SQLite가 내장되어 있다.** 이 프로젝트의 Node 22.22.2에서 **플래그 없이** 바로 돈다(실험 경고만 뜬다).

```js
import { DatabaseSync } from 'node:sqlite';
const db = new DatabaseSync(join(savesDir(), '..', 'gm.db'));
db.exec('PRAGMA journal_mode = WAL');
```

`better-sqlite3` 같은 네이티브 모듈이 필요 없다 → **`package.json`을 한 글자도 안 건드린다**(대원칙 유지).
네이티브 빌드가 없으니 ARM(Oracle)이든 x86이든 배포도 그대로다.

> 실험 단계 API라 향후 시그니처가 바뀔 수 있다. `server/db.js` 한 파일로 감싸서, 나중에 바꿔야 하면 그 파일만 고치면 되게 한다.
> `persistence.js`가 이미 그 방식으로 설계돼 있으니 결이 같다.

### 3-3. 무엇을 담고 무엇을 안 담나

**원칙: DB에는 「너는 누구인가」와 「스냅샷에서 다시 만들 수 있는 색인」만 담는다.**
그러면 DB가 통째로 날아가도 세계는 안 죽는다. 스냅샷을 훑어 색인을 재생성하고, 계정만 백업본에서 되살리면 된다.

담는 것:

```sql
-- 유일한 「원본」 데이터. 이것만 백업하면 된다.
CREATE TABLE account (
  id            TEXT PRIMARY KEY,   -- 영문·숫자 소문자 정규화 키 (표시용 아님)
  display_name  TEXT NOT NULL,      -- 한글 허용. 화면에 뜨는 이름
  token_hash    TEXT NOT NULL,      -- 이 브라우저를 조용히 증명
  recovery_hash TEXT,               -- 「개척자의 증표」. 다른 기기용. 나중에 채워도 되게 NULL 허용
  created_at    INTEGER NOT NULL,
  last_seen_at  INTEGER NOT NULL
);

-- 「내 정착지 목록」. 스냅샷에서 재생성 가능.
CREATE TABLE membership (
  game_id      TEXT NOT NULL,
  account_id   TEXT NOT NULL,
  avatar_id    TEXT NOT NULL,       -- 세계 안에서의 키. account.id와 같아도 되고 달라도 된다
  joined_at    INTEGER NOT NULL,
  last_seen_at INTEGER NOT NULL,
  PRIMARY KEY (game_id, account_id)
);

-- 방 색인. listGames() 를 대체한다. 스냅샷에서 재생성 가능.
CREATE TABLE game_index (
  game_id      TEXT PRIMARY KEY,
  invite_code  TEXT UNIQUE,         -- 사람이 부를 수 있는 짧은 코드 (§5-2)
  settlement   TEXT,                -- 정착지 이름
  tier         INTEGER, tick INTEGER, phase TEXT,
  created_at   INTEGER, last_tick_at INTEGER,
  loaded       INTEGER NOT NULL DEFAULT 0   -- 지금 메모리에 떠 있나 (§5-3)
);
```

**안 담는 것**: 자원(석재·목재), 건물, 타일, 안개, 주민, 동료, 연구, 캐릭터 스킬·레벨·능력치, 마지막 위치.
전부 `nation.*` 안에 있고 `saveSnapshot`이 세계를 통째로 굳혀 `saves/{gameId}/snapshot.json`에 쓴다. 그대로 둔다.

세 가지 이유다.
① 스탯은 **방마다 다르다** — 같은 아이디로 A에선 채집 12레벨, B에선 1레벨인 게 정상인데 계정에 매달면 새어나간다.
② 세이브가 「그 순간의 세계 전부」가 아니게 되면 결정론·되돌리기·재현 검증이 무너진다.
③ 지금 저장은 임시 파일 → 이름 바꾸기 원자적 교체 한 번인데, 저장소가 둘로 갈리면 자원은 줄었는데 스탯은 안 오른 반쪽 상태가 생긴다.

### 3-4. 파일 배치

```
/var/data/            ← 볼륨 마운트 (Railway) 또는 /opt/gm/data (Oracle)
  ├─ gm.db            ← SQLite. SAVES_DIR 과 같은 볼륨에 둔다
  ├─ gm.db-wal
  └─ saves/
       └─ g_xxx/snapshot.json …
```
환경변수는 이미 있는 `SAVES_DIR`을 그대로 쓰고, DB 경로는 `GM_DB` 하나만 새로 만든다(없으면 `SAVES_DIR`의 형제로 자동).

## 4. GitHub Pages 배포

### 4-1. 왜 나누나

Pages는 정적 파일만 준다 → Node가 못 뜬다. 그래서 **클라만 Pages, 서버는 별도 호스팅**이고 둘이 크로스 오리진으로 붙는다.
덤으로 정적 파일 대역폭이 서버에서 빠진다(§1-2).

★ 서버의 `express.static(PUBLIC_DIR)`은 **그대로 둔다.** 서버 주소로 직접 들어가면 same-origin이라 CORS도 CDN도 무관하게 그냥 된다.
Pages는 제출 요건용 진열창, 서버 직접 주소는 **문제가 생겼을 때의 안전한 백업 경로**다. 심사 때 이 이중화가 값을 한다.

### 4-2. 클라 수정 — 네 군데

**① 서버 주소를 한 곳에서 정한다.** `public/js/state.js` 맨 앞이나 새 파일 하나에:

```js
/* ★ Pages 사본만 다른 오리진의 서버를 본다. 서버가 직접 서빙할 때는 빈 문자열 = 같은 오리진. */
GM.SERVER = location.hostname.endsWith('github.io') ? 'https://⌐서버주소' : '';
```
빌드 스텝이 없는 프로젝트라 치환 워크플로를 만들지 않는 게 맞다. 이 한 줄이면 로컬·서버직접·Pages 세 경로가 전부 산다.

**② socket.io 클라이언트를 CDN에서 받는다.** `public/index.html:171`

```html
<!-- 전 -->
<script src="/socket.io/socket.io.js" onerror="window.__socketIoMissing=true"></script>
<!-- 후 — 서버의 socket.io 4.8.1 과 판을 맞춘다 -->
<script src="https://cdn.socket.io/4.8.1/socket.io.min.js" crossorigin="anonymous"
        onerror="window.__socketIoMissing=true"></script>
```
절대경로 `/socket.io/...`는 Pages(`/regiond/` 하위)에서 404다. CDN이 걸리면 대안은 부팅 때 `GM.SERVER + '/socket.io/socket.io.js'`를 동적 삽입하는 것.

**③ 소켓과 REST가 그 주소를 쓰게 한다.** `public/js/net.js`

```js
socket = global.io(GM.SERVER || undefined);          // connect() 안
return fetch(GM.SERVER + path, opt).then(…);          // rest() 안
```

**④ 상대경로 자산은 손댈 것이 없다.** `css/main.css`, `js/*.js`, 폰트 모두 상대경로라 `/regiond/` 하위에서 그대로 뜬다.

### 4-3. 서버 수정 — CORS 한 군데

socket.io는 이미 `cors: { origin: '*' }`로 열려 있다. **그런데 express REST에는 CORS 헤더가 없다** —
`fetch('/api/config')`가 Pages에서 막힌다. `cors` 패키지를 추가하지 말고(package.json 무변경) 미들웨어 세 줄로 끝낸다.

```js
// ★ Pages 사본이 /api/* 를 부를 수 있게 — 알려진 출처만 연다
const ALLOW = new Set(['https://dudejrtjdrp.github.io', 'http://localhost:3000']);
app.use('/api', (req, res, next) => {
  if (ALLOW.has(req.headers.origin)) res.setHeader('Access-Control-Allow-Origin', req.headers.origin);
  if (req.method === 'OPTIONS') return res.sendStatus(204);
  next();
});
```
socket.io 쪽 `origin: '*'`도 같은 화이트리스트로 좁히는 게 맞다.

### 4-4. 워크플로 — `.github/workflows/pages.yml`

`public/` 만 발행한다. 저장소가 `dudejrtjdrp/regiond` 이므로 주소는 `https://dudejrtjdrp.github.io/regiond/` 가 된다.

```yaml
name: Deploy client to GitHub Pages
on:
  push:
    branches: [main]
    paths: ['public/**', '.github/workflows/pages.yml']
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - name: Jekyll 끄기 (밑줄로 시작하는 파일이 사라지지 않게)
        run: touch public/.nojekyll
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: public
      - id: deployment
        uses: actions/deploy-pages@v4
```

저장소 **Settings → Pages → Source** 를 `GitHub Actions` 로 한 번만 바꿔 두면 된다.

### 4-5. 검증 순서

1. `https://dudejrtjdrp.github.io/regiond/?mock=1` → 서버 없이 화면이 도는가 (정적 배포 자체의 검증)
2. `https://…/regiond/` → 콘솔에 CORS·404가 없는가, `/api/config`가 200인가
3. 나무를 몇 번 베어 목재가 오르는가 (소켓 왕복)
4. 창을 닫았다 다시 열어 같은 정착지로 돌아오는가 (토큰·방 지속)
5. 다른 기기에서 증표로 들어가지는가

## 5. DB를 더 써먹을 곳

계정·방 목록만 넣자고 DB를 다는 건 좀 아깝다. 같은 테이블 몇 줄로 따라오는 것들을 값어치 순으로 적는다.

### 마감 전에 값을 하는 것

**5-1. `listGames()` 대체 (필수)**
지금은 방 목록 하나 만들려고 **모든 스냅샷을 읽는다**. 방이 100개면 160MB를 디스크에서 긁는다.
방이 영구적으로 남기 시작하면 바로 아파온다. `game_index` 한 방 쿼리로 끝난다.

**5-2. 사람이 부를 수 있는 초대 코드**
지금 초대 코드는 `g_252954915_mshk52sh` 다. 전화로 못 부르고, 심사위원에게 안내하기도 민망하다.
`invite_code` 컬럼에 `달빛-여우-37` 같은 3어절 코드를 매핑하면 입으로 전달된다.
게임 톤과도 맞고, 구현은 단어표 두 개 + 유일성 검사가 전부다. **체감 대비 비용이 가장 싼 항목.**

**5-3. 무인 방 언로드 판단**
지금 방은 `games` Map에 영원히 남고 타이머가 계속 돈다. 월드 객체(1.6MB급)가 통째로 메모리에 눌러앉는다.
512MB 인스턴스에 방이 수십 개 쌓이면 계정보다 이게 먼저 터진다.
`last_seen_at`을 보고 "N분째 아무도 없는 방"을 스냅샷 저장 후 언로드하고, 다시 들어오면 `getOrCreateGame`이 알아서 되살린다
(그 경로는 **이미 구현돼 있다**). `loaded` 컬럼으로 지금 몇 개가 떠 있는지도 바로 본다.

**5-4. 에러·예외 수집**
QA-A가 「재입장하면 낫는」 동기화 버그군 8종인데, 이런 건 재현이 어려워서 로그가 곧 생명이다.
서버 예외와 클라 `window.onerror`를 `error_log` 테이블에 쌓으면, 팀원 셋이 각자 플레이한 결과가 한 곳에 모인다.
지금은 각자 콘솔을 캡처해서 옮기는 중일 텐데 그게 없어진다.

**5-5. 플레이 텔레메트리**
`npm run simulate`는 봇 시뮬이다. 진짜 사람이 **며칠차에 죽는지, 어느 웨이브에서 무너지는지, 무엇을 먼저 짓는지**가 쌓이면
QA-E 밸런싱의 근거가 봇 추정에서 실측으로 바뀐다. 그리고 이 수치는 **게임소개 PDF에 그대로 실을 재료**이기도 하다
("평균 생존 N일, 첫 붕괴 지점은 3파" 같은 문장은 심사에서 힘이 있다).
익명 지표만 담는다 — 아이디와 묶을 이유가 없다.

### 마감 뒤에 어울리는 것

**5-6. 명예의 전당** — 지금까지 세워진 정착지들의 최고 티어·생존 일수·인구를 타이틀 화면에 흘린다.
`game_index`에 이미 있는 컬럼으로 만들 수 있다. 접속자가 없어도 세계가 굴러가는 이 게임의 성격과 잘 맞는다.

**5-7. 일일 시드 도전** — 이 게임은 **결정론 설계**라 시드 하나면 땅이 완전히 재현된다.
"오늘의 씨앗"을 하나 정해 모두가 같은 땅에서 도전하고 기록을 겨루는 모드가 거의 공짜로 나온다. 리더보드는 DB.
설계의 강점을 그대로 기능으로 바꾸는 항목이라, 여유가 생기면 1순위로 추천한다.

**5-8. 계정 단위 업적** — 스탯은 방마다지만 「정착지 셋을 세웠다」 같은 건 계정에 붙어도 된다.

**5-9. 닉네임 예약·금칙어** — 유일성 검사에 얹으면 된다.

## 8. 지금까지 개발된 것 — 작은 단위 세부 현황

배포 전에 한 번 더 훑기 쉽도록, 지금까지 구현된 내용을 기능 하나씩 잘게 쪼개 적는다. 아래 항목은 README의 v3 계열과 최근 유적 작업을 실제 동작 단위로 다시 풀어쓴 것이다.

### 8-1. 시작과 기본 루프

- 타이틀 화면이 따로 있고, 새 정착지 생성 / 초대 코드 참여 / 이어하기가 분리돼 있다.
- 새 정착지는 이름과 난이도를 먼저 고르고, 그 다음 마차에 오른다.
- 시작 상태는 주민 0명에서 출발한다.
- 플레이어는 마차 도착 오프닝을 거쳐 월드로 들어간다.
- 손으로 캐는 기본 루프가 있고, 도끼질과 이동이 가장 먼저 열린다.
- 게임은 끝이 없는 정착지 성장 구조로 설계돼 있다.

### 8-2. 진행 감독과 해금

- 콘텐츠 사슬 10장이 있고, 장이 순서대로 문을 연다.
- 시간만으로는 아무것도 열리지 않고, 플레이어 행동이 문을 연다.
- 감정의 날은 자동이 아니라 감정소를 세우고 눌러야 열린다.
- 장 목표는 퀘스트 카드와 마커로 따라가게 된다.
- 잠긴 기능은 화면에 아예 숨긴다.
- 같은 오류가 반복되면 해결 말풍선과 마커가 붙는다.

### 8-3. 성장과 정착지 운영

- 정착지 티어가 0부터 6 이상까지 올라간다.
- 티어가 오르면 영토 반경이 넓어진다.
- 주민은 주거 수용력과 식량 여유와 매력도 조건으로 들어온다.
- 주민 이름과 외형이 랜덤으로 붙는다.
- 주민 능력치는 태어날 때 한 번 정해지고 고정된다.
- 주민 명부와 선택 패널이 따로 있다.
- 역할군이 있고, 건축가·국방·성녀 같은 개성 차이를 가진다.

### 8-4. 행동과 스윙

- 액션은 스윙 단위로 판정된다.
- 스윙 쿨다운과 사거리가 서버에서 계산된다.
- 장비 단계에 따라 도구가 열린다.
- 광역 스윙이 있어 일정 숙련도부터 옆 타일까지 스친다.
- 자동 플레이가 켜지면 잠시 멈췄다가 다시 이어 간다.
- 멀티 상황에서는 하차 전 동결이 적용된다.

### 8-5. 월드와 자원

- 월드는 384×384 크기다.
- 자원은 숲 군락, 딸기 들, 바위 지대, 강가 어장처럼 지역 단위로 배치된다.
- 시작 영토 안은 빈 땅이다.
- 자원은 고갈되면 그루터기처럼 남고, 나중에 다시 생긴다.
- 군락과 자원은 재현성이 있어 같은 씨앗이면 같은 배치가 나온다.
- 숨은 궤와 유적이 따로 있다.

### 8-6. 전투와 생태계

- 상시 생태계가 따로 있어서 짐승과 적이 들에 산다.
- 링0, 링1, 링2처럼 위험 구역이 나뉜다.
- 링2 진입 시 경고가 뜬다.
- 울타리 안은 안전 지대로 취급된다.
- 검을 휘두르면 짐승을 잡고 드롭을 얻는다.
- 사냥한 고기는 식량으로 환산된다.
- 엔드리스 웨이브가 따로 흘러간다.
- 실시간 전투는 적·민병·플레이어가 함께 들어가는 구조다.

### 8-7. 유적과 탐험

- 유적은 1×1부터 4×4까지 크기가 다르다.
- 큰 유적일수록 오래 걸리고 보상이 커진다.
- 방 단위 진행이 있고, 다 뒤진 자취는 회색 폐허로 남는다.
- 유적은 한 번 캐고 끝나는 게 아니라 여러 방과 여러 카드로 나뉜다.
- 얕은 방과 깊은 방 카드 풀이 분리돼 있다.
- 단서는 다음 자취로 이어지는 고리를 만든다.
- 단서는 좌표를 직접 노출하지 않는다.
- 한 자취에서 단서는 한 번만 나온다.

### 8-8. RPG와 장비

- 주민마다 근면, 힘, 손재주, 용기 수치가 있다.
- 장비는 무기와 방어구로 나뉜다.
- 대장간에서 장비를 벼린다.
- 인첸트가 장비에 붙는다.
- 연구 트리로 석탄 채굴, 증기기관, 철로, 정유가 열린다.
- 철로는 이동 속도를 바꾼다.

### 8-9. 동료와 자동화
