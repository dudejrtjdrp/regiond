## B. 영역별 판정 요약

### B1. 대화/NPC 대사
- 대화창 그릇(`GM.dialogue.open`)은 5개 모듈이 공유하는 완성 자산. 툴박스는 미존재(신규).
- **적 대사 시스템은 0%** — 현재 침공 배너 한 줄뿐. 재활용 가능: `templates.ko.json`+`server/expression/templates.js`(문장풀+변수치환 엔진), `statRng`(결정론적 선택), raider 일러스트. 주의: `combat.js:19,35`가 전투 시 대화창 강제 close.
- 적 종류/상황별 대사는 `data/creatures.json`·`waves.json`에 대사 필드를 신설하고 템플릿 엔진에 연결하는 신규 작업.

### B2. 탐험 콘텐츠 (유물/유적/신전/숨은길) — **핵심: 루프는 이미 닫혀 있다**
서버에 완결 구현된 루프: 유적 방 스윙 → 결정 카드 → 깊은 방 dig → `clues.js dropClue()` (3개마다 신전 단서, 아니면 다음 유적 안개+방위/지형 단서) → `temple.js` 3단(수수께끼→수호자→안치소) → 등급별 유물 지급 → registry/도감/연대기 기록. `artifactHunt` 원정 트래커 UI도 존재.

문제는 전부 "보이지 않음": A2(도감 사망), 게이트 오배치(`artifactHunt`·`decisionQueue`가 `councilOn`=10장 게이트 안 → 탐험 안내 UI가 후반까지 부재), A5/A12/A13(이음매 끊김).

- 유물 71종 전량 lore+hint 집필 완료. 단 기존 50종 hint가 경로가 아닌 희귀도 서술(유물기획 §20-1.3 부채) → 재집필 대상.
- **유물 조사 반복 선택**: 클라(`council.js:75-76,103`)만 고치면 안 됨 — 서버 `commands.js:1046` `decide`가 큐에서 splice하는 1회성 규약. 옵션별 소진 방식으로 규약 변경 + **반복 시 월드 난수 대신 `statRng(seed:ruin:node:room:opt)` 사용 필수**(결정론 보호).
- **숨은 길**: 별도 시스템 아님 — trails(흔적 17사슬+16마이크로)+clue 안개의 서사적 표현. 사후 조회 UI 없음 → 도감 4번째 탭 "밟아 온 길" 신규.
- **신전**: 야외 3단 결정 카드 100%, 내부 맵/에셋 0%(설계 정본이 "새 씬 금지" 명시). 최소비용 경로: `council.js:105 templeInterior()` 도식을 배경 일러+안치대 3상태로 승격. 수호자는 현재 야외몹과 동일 소환이라 보스감 부재.
- 신전 위치 불안정 리스크: `temple.js:31` 캐시 키가 노드 수 포함 → 노드 삭제 시 신전 이동 가능. 개편 시 수정.

### B3. UI/HUD/메뉴
- 상시 UI 27개 전수 목록 확보(에이전트 보고). 좌상단 8개+우측 3개+하단 중앙 3중 점유.
- 알림 채널 3개(토스트/배너/알림스택)가 독립, 통합 큐·우선순위 없음. 알림스택은 7개 초과분 무단 절단(`hud.js:574`). 자동숨김은 계열별 제각각(2.6~14초) — "5초 정책"은 `kind`별 분기로 일원화 필요(경고성은 해소까지 유지가 설계 의도).

- 스폰: A11. "행군 침입" 구조는 camps를 스폰 앵커로 승격+일틱 전진으로 구현 가능. `maxSeconds:120` 재보정 동반 필수.

### B9. 성능
Sprint 3 패스 잔여분. 우선순위(효과/난이도/위험):
1. **계측 먼저** — `GM.world.frameStats()`에 structuresMs/dressingMs/apronMs/SCALED.size 추가 후 실측 (코드베이스 자체 방침)
2. 저위험 즉효(반나절): drawLandmarks 조건 순서, drawTerrainAtmosphere worldToScreen→X/Y 치환(초당 24만 객체 제거), 등불 루프 break, drawTerritory 그라디언트 캐시, **SCALED FIFO→LRU**(후반 절벽 붕괴 패턴과 일치, 최우선 실측), drawStructures 컬링 전진, detectCompletions 제거, drawBiomeDressing 죽은코드 삭제
3. 구조: drawBuildingApron 오프스크린 캐시(건물당 프레임마다 ~150 path 명령 → 최대 병목 후보), 정적/동적 레이어 분리
4. 서버: 저장 stringify worker 이관, structuredClone 얕은 클론 절충(**결정론 테스트 통과 전제**)
- 네트워크는 델타+AOI 이미 구현. collectionDelta의 행별 stringify만 rev 방식 전환 후보.

### B10. 탐험 힌트 설계 (레퍼런스 리서치 결과 적용안)
현재 clue 시스템(방위+지형 한 줄+안개 9타일)은 레퍼런스의 "범위 확정+지점 추론" 패턴과 이미 일치. 부족한 것:
- **저널 축적**(Outer Wilds 경량화): 단서 카드 목록+상태 뱃지(미해결/추정됨/완료). 서버에 `clueGiven/clueSeen/templeClues` 이미 존재 → 도감 탭에 노출만 하면 됨

- **주민 해독 단계**(정착지 성장↔탐험 연결): 학자 NPC가 단서 번역 — P2 후보
- hint 50종 재집필: 희귀도 서술→경로 은유
