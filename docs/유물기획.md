## §20-0. 목표와 설계 철학

**목표 한 줄:** 유물을 얻는 순간 "와, 대박이다" — 유물은 아이템이 아니라 **게임의 최종 목표 중 하나**다. 플레이어가 유물을 찾아 탐험하고, 얻으면 방 전체(전설은 서버 전체)가 알고, 발견자의 이름이 세계의 기록에 남는다.

**현행 진단 (왜 리워크인가):**
1. 효과가 약하다 — 대부분 ±8~20% 소형 배수, 소모형은 고정치(곡물 120 등)라 후반에 무의미.
2. 획득이 밋밋하다 — 어전 회의 12% 굴림·유적 카드 40% 굴림뿐, 연출은 유물함 배지 수준.
3. 기억에 남지 않는다 — 발견자·날짜·소유 기록이 없고, 도감(codex)에 유물 층이 없다.
4. 희소감이 없다 — legendary가 상자에서 5%로 그냥 나온다. 「단 하나뿐인 것」이 없다(용 전리품 제외).

**설계 철학 5원칙:**
1. **수직이 아니라 수평으로 강하게.** 고유·전설 유물은 수치가 아니라 **플레이 방식**을 바꾼다(낮 생산 특화, 설산 개척, 부활…). 같은 등급 안에서 효과 축을 분산해 「모두가 같은 유물」이 나오지 않게 한다(§20-10).
2. **희소는 경로로 만든다.** 고유·전설은 상자에서 안 나온다. 몸으로 가서(링3 신전·설산 최심부·용) 얻는다 — 탐험기획(§18) 링 구조가 유물의 지도다.
3. **연출과 판정은 분리한다.** 서버는 즉시 지급·기록하고, 연출은 클라 로컬 재생(스킵 가능). 서버 권위 불변.
4. **기록이 보상이다.** 최초 발견자·발견 날짜·획득 횟수·현재 소유자·Lore — 얻는 것 자체가 업적이 되게 한다.
5. **재활용 최대화.** 기존 50종·collectHooks 훅 체계·유적 카드·cache·사슬(trails)·도감 4층·연대기·컷신·fx/sfx — 전부 그대로 쓰고 위에 얹는다. 신규 파일은 최소로.

## §20-1. 등급 체계 재편

현행 4등급(일반 55 / 레어 32 / 유니크 8 / 레전더리 5, 상자 단일 풀)을 **의미가 다른 4등급 + 직교 속성 2종**으로 재편한다.

| 등급 | 이름 | 역할 | 나오는 곳 | 연출 티어 |
|---|---|---|---|---|
| common | 일반 | 소소한 편의·이야기 조각 | 어전 회의 상자·유적 카드·cache(링0~1) | T1 |
| rare | 레어 | 뚜렷한 강화 (한 축 +15~35%) | 상자·유적 카드·cache(링1~2)·사슬 결말 | T2 |
| unique | **고유** | **플레이 방식을 바꾼다** (게임 체인저) | 상자 불가 — 링3 cache 저확률·고대 신전·특수 사슬 결말·국가 이벤트 | T3 |
| legendary | **전설** | **방에 단 하나** — 왕국의 상징 | 확정 경로 4곳뿐 (§20-4) | T4 |

- **직교 속성 (등급과 별개):** `curse`(저주 — 강력하지만 명확한 페널티, §20-6) · `setKey`(세트 — 모으면 추가 효과, §20-5).
- **상자 풀 축소가 핵심이다.** 어전 회의 상자·유적 카드의 기본 풀은 일반+레어뿐(가중치 60/40 재정규화). 고유·전설이 상자에서 빠지는 순간 「탐험해야 하는 이유」가 생긴다.
- 기존 유니크 등급이 맡던 외형(cosmetic) 5종은 일반·레어로 재배치(§20-2 표). 「유니크=고유」는 게임 체인저 전용 칸으로 재정의.
- 세이브 호환: 등급은 key가 아니라 정의 테이블 소관이므로 옛 세이브의 보유 유물은 그대로 산다. 재분류로 효과만 상향된다.

## §20-7. 획득 연출 스펙 (R2) — 「연출은 클라, 판정은 서버」

서버는 즉시 지급·기록·방송하고(§20-11), 클라는 push를 받아 등급별 연출 티어를 로컬 재생한다. 클릭·E·ESC로 언제든 스킵. 「모달 자동 팝 금지」 원칙과의 관계: 획득 연출은 **플레이어 자신의 행동(조사·전투·개봉)의 즉각 피드백**이므로 발동자 본인에게만 전체 연출을 재생하고, 같은 방 다른 플레이어에게는 배너·월드 이펙트만 보여준다(남의 화면을 빼앗지 않는다).

| 티어 | 대상 | 연출 시퀀스 (발동자 화면) | 다른 플레이어 |
|---|---|---|---|
| T1 | 일반 | 현행 유지 — 토스트 + 유물함 배지 + 획득음(소) | 없음 |
| T2 | 레어 | 상자 개봉 모달: 카드 뒤집기 0.6s → 등급색 글로우 → 이름·효과 → 전용 차임 | 방 토스트 1줄 |
| T3 | 고유 | 화면 어둡게 0.4s → 획득 지점 **빛기둥**(fx) → 카메라 줌인 → **유물 카드**(도트 아이콘 4배 확대·등급 리본·lore 1줄 타자기·발견자명) → 금빛 파티클 → 도감 등재 스탬프 | 방 배너 + 획득 지점에 작은 빛기둥(월드 이펙트) |
| T4 | 전설 | T3 전체 + 진입 슬로모(timeScale 연출용 0.5× 2s, **클라 로컬만** — 서버 시계 불변) + 화면 비네트 + 전용 팡파레 + 연대기 대문 기록 컷 | **방 전체 화면에 하늘 빛기둥** + 배너 + 팡파레(소리 축소판). **서버 전역 알림**(아래) |

- **전역 알림:** 전설 획득 시 서버가 모든 방에 push — 「엘도린의 군주 ○○이(가) 전설의 유물 「용의 심장」을 발견했습니다.」 문구는 `data/templates.ko.json`에. 잼에서는 같은 서버 프로세스의 전 방(io.emit), 잼후 R5에서 persistence 연동.
- **유물 카드 UI:** 대화창(§18-6)과 같은 종이·나무 시각 언어. 구성: 등급 리본(등급색) / 도트 아이콘(atlas 재활용, image-rendering: pixelated 4배) / 이름(Galmuri11 대형) / 효과 요약 / lore 1~2줄(타자기 18ms) / 「최초 발견: ○○ · N년 M일」.
- **SFX:** `sfx.js` 절차 합성 방식 그대로 신규 3종 — rare 차임(3음 아르페지오), unique 합창 패드(장3화음 스웰), legendary 팡파레(5음 + 저음 드론). 외부 오디오 에셋 불필요.
- **아이콘:** 유물 개별 도트 아이콘은 에셋 명세에 이관(§20-12 말미). R2 시점에는 카테고리 아이콘 + 등급 프레임(절차 렌더)으로 선대응.

## §20-8. 유물 도감 — 「세계의 역사」 (R3)

도감(codex.js, J키)의 4층 구조를 재활용해 **유물 탭**을 추가한다. 「잠긴 것은 부재다」(§11-1) 원칙 유지 — 서버가 준 카드만 그린다.

| 층 | 조건 | 보이는 것 |
|---|---|---|
| 0 | 미발견 | **실루엣 + 등급색 물음표** — 「이 세계 어딘가에 있다」. 힌트 1줄(획득 경로의 은유: 「북쪽의 얼음 밑에서 잠들어 있다」) |
| 1 | 방에서 누군가 발견 | 이름·등급·아이콘 |
| 2 | 보유(나라) | 효과 전문 + lore 전문 |
| 3 | 기록 | **최초 발견자(캐릭터명) · 발견 날짜(게임 내 N년 M일 + 실제 날짜) · 획득 횟수(방 누적) · 현재 소유(나라/봉인 여부)** |

- 발견 기록은 `nation.artifacts[]` 엔트리 확장(`foundBy`, `foundTick`, `foundDate`)과 방 등록부 `world.artifactRegistry`(§20-11)가 정본. 연대기에도 kind: 'artifact'로 이미 남는 것을 유지·확장(발견자명 포함).
- 전설 4종은 도감 맨 위 별도 단(「왕국의 상징」)에 크게 — 미발견이어도 실루엣이 보여서 목표가 된다.
- 잼후(R5): 서버 전역 도감 — 방을 넘는 발견 기록(「이 서버 최초 발견: ○○」)을 persistence에 적재.

## §20-9. 획득 경로 재설계 — 「탐험의 동기」 (R1 확률 + R4 콘텐츠)

낮=탐험 창 / 웨이브=귀환의 밀당 리듬(§18-0) 위에 유물 경로를 얹는다. 모든 굴림은 statRng(시드:경로:노드id) — 결정론 유지.

| 경로 | 풀 | 확률/조건 (balance.artifacts 신규 키) | 배치 |
|---|---|---|---|
| 어전 회의 상자 | 일반·레어 | `chestChancePerCouncil` 0.12 유지, `gradeWeights` {common 0.60, rare 0.40} | R1 |
| 유적 카드 artifactRoll | 일반·레어 (+gradeBoost) | 카드별 0.4 유지, `ruinGradeBoost` 경로 유지 | R1 |
| 탐험 cache | 링별 차등 | 링0~1: 일반 중심 0.30 / 링2: 레어 중심 0.35 / 링3: 0.40 + **고유 0.05** (`ringDropTable`) | R1 확률, 링3 고유 풀은 R4 |
| 단서 사슬 결말 | 원형별 | 원형 4(폐촌)·8(원정대) 결말 유물 확정, 링3 사슬 결말 고유 0.15 | R4 (잼후 사슬 16종 중 잼 편입분만) |
| 고대 신전 (신규) | **고유·전설** | 링3에 시드 고정 배치 1~2개. 유적 카드의 **3단 연속 결정**(수수께끼→시련→안치소) 확장판 — 실패 시 다음 날 재도전 | R4 |
| 드래곤 최초 격퇴 | 전설 (용의 심장) + fixed (왕관의 조각) | 확정, 최초 1회 | R4 |
| 국가 이벤트 보상 | 고유 1종(기관장의 인장)·레어 | 이벤트 8종(세계관 §4) 중 지정 이벤트의 성공 보상 | R4 (W4와 같은 배치 권장) |
| 발견 확률 상한 | — | `discoverChanceCap` 0.25 → **0.30** (행운의 부적 +5% 수용) | R1 |

- **고대 신전이 「던전 보스·고대 신전·숨겨진 유적」 요구의 잼 버전 답이다.** 별도 던전 씬을 만들지 않고, 유적 카드 시스템(결정 큐·decide 프로토콜)의 3단 연속판 + 수호 짐승 전투(기존 creature 전투 재활용)로 만든다. 신규 씬·신규 전투 시스템 없음.
- **이벤트 후 등장:** 별똥별 낙하(원형 14) 등 영구 흔적 사건과 유물의 결합은 잼후(사건 시스템 자체가 잼후 3). 잼에서는 국가 이벤트 보상 경로가 그 자리를 맡는다.
- 획득 경로는 도감 0층 힌트 문장과 1:1 대응 — 힌트가 곧 지도가 된다.

## §20-10. 밸런스 프레임 — 「전부 세되, 같은 답은 없게」

1. **파워 버짓:** 등급별 「국가 산출 기대 기여」 상한 — 일반 ≤3% · 레어 ≤8% · 고유 ≤15%(단 축이 좁아야 함) · 전설 ≤20%(획득 난도가 담보). 저주는 순기여가 등급 기대치 이내로 떨어지게 페널티를 잡는다.
2. **축 분산 규칙:** 같은 등급 안에서 효과 축(생산/전투/무역·외교/탐험/방어/사기·편의) 어느 하나가 40%를 넘으면 재설계. 고유 9종은 현재 생산 2 · 전투 3 · 탐험 2 · 무역 1 · 현대화 1.
3. **시뮬 게이트:** ① `npm test` 그린(artifacts 훅 테스트 확장 포함) ② `npm run simulate` 시드42 체크포인트 4/4 유지 ③ **시드77 웨이브5 55% 잔존 이슈**(밴드 60~80)에 전투 유물 상향이 얹히므로, R1 머지 전 시드77 재측정 — 초과 시 조임 다이얼은 유물이 아니라 기존 계획대로 `waves.battle.breach.damageScale` 8→6~7.
4. **유물 자동 획득 시나리오:** simulate에 「유물 풀보유」 옵션 시나리오 1개 추가 제안(R1) — 최대 강화 상태의 이탈 폭을 계측해 상한을 데이터로 관리.
5. **중첩 규칙 명문화:** 같은 축 배수는 곱연산(현행 collectHooks 유지), 동일 flag는 중복 무효, 세트 보너스는 단품과 합산. 「모두 같은 유물」 방지는 확률이 아니라 **경로의 방위 분산**(§20-5 세트 1처럼 사방으로 흩기)이 맡는다.

## §20-11. 데이터·프로토콜 변경 초안 (구현 계약)

### data/artifacts.json v2 — 엔트리 확장 (기존 필드 유지 + 추가)
```
{ "key", "name", "grade", "category", "role", "type", "desc", "effects": [...],   // 기존
  "lore": "2~3문장. 창세·방위·3국 모티프",                                        // R3
  "hint": "도감 0층 힌트 1줄 (획득 경로의 은유)",                                  // R3
  "setKey": "genesis" | "expedition" | null,                                      // R4
  "curse": true | 생략,                                                           // R1(기존 tradeoff 재표기)
  "exclusive": "room" | "server" | 생략,   // 전설. 잼=room, R5에서 server 전환    // R4
  "fxTier": 1~4 생략 시 등급 기본값,                                               // R2
  "acquireVia": ["chest","ruin","cache3","chain:expedition","temple","dragon","event"] }  // R1
```
- 세트 정의는 `data/artifacts.json`에 `sets: { genesis: { pieces:[4키], bonuses:{ "2": [...효과], "4": [...] } } }` 블록 신설.
- balance.artifacts 신규 키: `gradeWeights`(60/40 재정규화) · `ringDropTable` · `templeRetryDays` · `discoverChanceCap` 0.30 · `sealCostGold`(저주 봉인 비용).

### 상태·엔진
- `nation.artifacts[]` 엔트리 확장: `{ key, obtainedTick, consumed, foundBy(캐릭터명), foundDate({year,day}), sealed:false }`.
- `world.artifactRegistry`: `{ [key]: { foundBy, foundTick, count } }` — 방 등록부(도감 3층·전설 room 유일 판정의 정본). 옛 세이브 마이그레이션: 보유 엔트리에서 역생성, foundBy는 「전해지지 않음」.
- collectHooks 신규 op(안): `dayOutputBonus`(낮 한정) · `dodgeChance` · `critChance` · `reviveCharge` · `speciesDamageStack` · `auraTile`(설치형 반경) · `snowBuildUnlock` · `fogAutoReveal` · `moraleDeltaOnVictory` · `popInflowMultiplier` · `maxHpMultiplier` · `trailSenseDelta` · `trainCargoMultiplier` · `researchSpeedMultiplier`. 전부 기존 applyDescriptor 스위치에 case 추가로 수용 가능 — 새 집계 체계 불필요.
- 소모형 「N회 충전」 일반화: `owned.chargesLeft`를 두고 소진 시 consumed 전환(현행 1회 소모 로직의 확장).

### PROTOCOL (계약 변경 — 구현 시 PROTOCOL.md부터 갱신)
- push `artifact_found` 확장: `{ artifact, grade, fxTier, foundBy, lore1줄, nodePos? }` — nodePos는 방 공용 빛기둥 좌표.
- push 신설 `artifact_global`(서버 전역, 전설만): `{ nationName, foundBy, artifactName }` — io.emit. 문구는 templates.ko.json.
- view: `nation.artifacts` 엔트리에 기록 필드 동봉, codex payload에 유물 층(잠긴 층은 부재 원칙 동일).
- 명령 신설: `sealArtifact {key}`(저주 봉인) · `plantArtifact {key, x, y}`(세계수 설치) · `tyrantPick {role}`(폭군의 왕관 선택). 전부 기존 명령 화이트리스트 방식.

### 잼후 R5 스케치 (설계만, 구현 보류)
- persistence에 서버 전역 `globalArtifactRegistry` — 전설 `exclusive:"server"` 전환, 전역 도감·「서버 최초 발견」.
- 방 간 쟁탈: 방 간 상호작용(전쟁·외교) 시스템이 전제라 별도 기획 필요. 최소 선행 형태는 「전설 보유 방이 서버 목록에 공개 → 도전장(비동기 침공 시뮬) → 승리 시 이전」. 왕국의 상징(성 외형·칭호)은 R4의 방 유일 버전에서 먼저 구현되므로 재사용.
