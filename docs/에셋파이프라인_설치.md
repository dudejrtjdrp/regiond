# 에셋 파이프라인 설치 가이드 (Windows + RTX 3060 12GB)

작성 2026-08-07 · 대상: 갈래말래(Toji) 픽셀아트 자동 생성 파이프라인
관련 정본: `docs/아트바이블.md`(아트 규칙) · `docs/SPEC_에셋파이프라인.md`(구현 계약)

이 문서 하나만 따라가면 `python tools/pipeline/generate.py ...` 한 줄로 아트바이블 규격 에셋이 나온다.
**총 소요 시간: 약 60~90분** (대부분 모델 다운로드 대기 시간)

**커스텀 노드는 설치하지 않는다. 정지도, 애니메이션도 마찬가지다.** 배경 제거·트림·팔레트 양자화·
프레임 슬라이싱을 전부 파이썬에서 하기 때문에, 워크플로우는 ComfyUI **코어 노드 11종**만 쓴다 —
정지용 8종(`CheckpointLoaderSimple`, `LoraLoader`, `CLIPTextEncode`, `EmptyLatentImage`,
`KSampler`, `VAELoader`, `VAEDecode`, `SaveImage`) + 애니 img2img용 3종(`LoadImage`,
`ImageScale`, `VAEEncode`). ComfyUI-Manager조차 필수가 아니다 — 설치하면 편하지만 동작에는 무관하다.

## 1. ComfyUI Windows portable 설치

1. 공식 설치 문서: <https://docs.comfy.org/installation/comfyui_portable_windows>
   릴리스 zip: <https://github.com/comfyanonymous/ComfyUI/releases> 의
   `ComfyUI_windows_portable_nvidia.7z` (최신 릴리스 자산)
2. **공백·한글이 없는 경로**에 압축을 푼다. 예: `D:\ComfyUI_windows_portable`
   (경로에 한글이 있으면 일부 노드가 파일을 못 읽는다.)
3. `run_nvidia_gpu.bat` 를 더블클릭한다. 콘솔에 `To see the GUI go to: http://127.0.0.1:8188` 이 뜨면 성공.
4. 브라우저에서 <http://127.0.0.1:8188> 접속 확인.

> **Portable vs Desktop:** 2026년 현재 ComfyUI는 설치형 Desktop 앱도 제공하지만, 이 파이프라인은
> **portable을 권장**한다. 모델 폴더가 `ComfyUI\models\` 로 눈에 보이고, 포트가 항상 8188로 고정되며,
> 프로젝트별로 통째로 복사·백업하기 쉽기 때문이다. Desktop을 쓰더라도 API는 동일하므로
> `config.json`의 `comfyUrl`만 실제 포트로 맞추면 파이프라인은 그대로 돈다.

RTX 3060 12GB는 SDXL 1024×1024 생성에 충분하다. 별도 `--lowvram` 옵션이 필요 없다.
(부족하다면 `run_nvidia_gpu.bat` 안의 실행 줄 끝에 `--lowvram`을 붙인다. 속도는 느려진다.)

## 2. 모델 다운로드 · 배치 (주력 구성)

**주력 조합: SDXL 1.0 + pixel-art-xl LoRA.**
선정 이유 — ① pixel-art-xl은 SDXL 1.0 전용 픽셀아트 LoRA로 사실상 표준이고 지금도 가장 널리 쓰인다,
② 12GB VRAM에서 1024px 32스텝이 여유롭게 돌아 후보 4장을 몇 분 안에 뽑을 수 있다,
③ 제작자가 "결과를 8배 nearest로 축소해서 쓰라"고 명시했는데, 이것이 우리 파이프라인의
1024px 생성 → 정수 다운스케일 → 팔레트 양자화 흐름과 정확히 맞물린다.

아래 세 파일을 **ComfyUI 폴더 안 정확한 위치**에 넣는다.

| 파일 | 넣을 위치 | 크기 | 다운로드 |
|---|---|---|---|
| `sd_xl_base_1.0.safetensors` | `ComfyUI\models\checkpoints\` | 6.94GB | <https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0/resolve/main/sd_xl_base_1.0.safetensors> |
| `pixel-art-xl.safetensors` | `ComfyUI\models\loras\` | 171MB | <https://huggingface.co/nerijs/pixel-art-xl/resolve/main/pixel-art-xl.safetensors> |
| `sdxl_vae.safetensors` | `ComfyUI\models\vae\` | 335MB | <https://huggingface.co/madebyollin/sdxl-vae-fp16-fix/resolve/main/sdxl_vae.safetensors> |

> **파일명을 바꾸지 말 것.** `tools/pipeline/config.json`의 `checkpoint`/`loras[0].name`/`vae` 값이
> 이 세 이름 그대로다. 이름을 바꾸려면 config.json도 같이 고쳐야 한다.

> **VAE를 따로 받는 이유:** SDXL 기본 내장 VAE는 fp16에서 검은 사각형/색번짐 아티팩트를 낸다.
> pixel-art-xl 제작자도 "fixed VAE(0.9 또는 fp16 fix)를 쓰라"고 명시한다. 픽셀아트는 색이 곧
> 품질이라 여기서 새는 색을 나중에 팔레트 양자화로 되살릴 수 없다.

받은 뒤 **ComfyUI를 재시작**한다. 그래야 모델 목록이 갱신된다.
(`Checkpoint Loader` 노드의 드롭다운에 세 파일이 보이면 정상. `generate.py`도 실행 시
`/object_info`로 이 목록을 읽어 파일명이 틀리면 생성 전에 한국어로 알려준다.)

### 대안 구성 (선택) — FLUX.1-dev + Modern Pixel art LoRA

디테일과 프롬프트 이해도를 더 원하고 장당 1~2분을 감수할 수 있다면 쓴다.
RTX 3060 12GB에서는 **fp8 또는 GGUF Q4 양자화본**을 써야 한다(원본 fp16 23GB는 안 올라간다).

| 파일 | 위치 | 다운로드 |
|---|---|---|
| `flux1-dev-fp8.safetensors` | `models\checkpoints\` | <https://huggingface.co/Comfy-Org/flux1-dev> |
| `ume_modern_pixelart.safetensors` (344MB) | `models\loras\` | <https://huggingface.co/UmeAiRT/FLUX.1-dev-LoRA-Modern_Pixel_art> |

트리거 워드는 `umempart`이며 프롬프트 맨 앞에 넣는다.
전환하려면 `config.json`의 `checkpoint`/`loras`를 바꾸고, 워크플로우의 `CLIPTextEncode` 두 개를
Flux용(`FluxGuidance` + 단일 CLIP) 그래프로 교체해야 한다. **주력 구성으로 먼저 안정화한 뒤에 시도할 것.**

## 3. Python 의존성

Python 3.10 이상이 필요하다. (`python --version` 또는 `py -3 --version`)
없으면 <https://www.python.org/downloads/windows/> 에서 설치하고 **"Add python.exe to PATH"를 체크**한다.

```bat
pip install pillow requests websocket-client
```

확인:

```bat
python -c "import PIL, requests, websocket; print('ok')"
```

> `websocket-client`가 맞다. `websockets`(다른 패키지)를 설치하면 `import websocket`이 실패한다.
> 이미 `websockets`가 깔려 있어 충돌하면 `pip uninstall websockets` 후 재설치한다.

프로젝트 `package.json`과 npm 의존성은 건드리지 않는다(SPEC 공통 제약).

## 5. config.json 확인

`tools/pipeline/config.json`에서 아래 값만 실제 환경과 맞으면 된다.

| 키 | 기본값 | 언제 바꾸나 |
|---|---|---|
| `comfyUrl` | `http://127.0.0.1:8188` | ComfyUI를 다른 포트로 띄웠을 때 |
| `projectRoot` | `"../.."` | **바꾸지 않는다.** config.json 위치 기준 상대경로다 |
| `checkpoint` | `sd_xl_base_1.0.safetensors` | 다른 체크포인트를 쓸 때 |
| `loras[0].name` / `.strength` | `pixel-art-xl.safetensors` / `1.0` | LoRA를 바꾸거나 세기를 조절할 때 |
| `vae` | `sdxl_vae.safetensors` | VAE 파일명이 다를 때 |
| `candidates` | `4` | 후보를 더/덜 뽑고 싶을 때 (3060 기준 4장에 약 3~5분) |
| `quantizeStrength` | `0.5` | 0.0=28색 유지, 1.0=16색까지 압축 |
| `timeoutSeconds` | `900` | 큰 캔버스나 Flux로 바꿔 느려졌을 때 |
| `anim.strategyByCategory` | 대부분 `anchor` | 카테고리별 애니 전략(§9-2) |
| `anim.frames` | `effect` 6 · `furniture` 4 … | 카테고리별 기본 프레임 수. 비우면 §9 표 |
| `anim.denoise` | 애니별 0.42~0.75 | **애니 품질 튜닝의 핵심 손잡이**(§9-4) |
| `anim.consistency` | IoU/색/크기 임계 | 프레임 일관성 경고 기준(§9-6) |

## 6. Claude Code 연동 (MCP)

프로젝트 루트에 `.mcp.json`이 이미 있다.

```json
{ "mcpServers": { "toji-assets": { "command": "node", "args": ["tools/asset-mcp/server.mjs"] } } }
```

Claude Code를 **프로젝트 루트에서** 실행하면 이 파일을 자동으로 읽고 승인 여부를 묻는다. 승인하면 끝이다.

자동 인식이 안 될 때 수동 등록:

```bat
claude mcp add toji-assets -- node tools/asset-mcp/server.mjs
claude mcp list
```

연동되면 다음 도구가 생긴다: `generate_asset` · `list_assets` · `qa_asset` ·
`apply_size_overrides` · `comfy_status`.

**연동 확인:** Claude에게 "comfy_status 실행해줘"라고 한다. ComfyUI 버전과 VRAM 여유가 보고되면 정상이다.
(Node 22가 PATH에 있어야 한다: `node -v`)

## 7. 스모크 테스트

ComfyUI가 켜져 있는 상태에서, **프로젝트 루트**에서 실행한다.

### 7-1. 접속 없이 프롬프트만 확인 (10초)

```bat
python tools\pipeline\generate.py --id test/style_probe --name "스타일 시험" ^
  --desc "a sturdy iron longsword with leather-wrapped grip" ^
  --category weapon --dry-run
```

조립된 프롬프트가 출력되면 설정 파일과 팔레트 로딩이 정상이다.

### 7-2. 실제 생성 (5~10분)

```bat
python tools\pipeline\generate.py --id test/style_probe --name "스타일 시험" ^
  --desc "a sturdy iron longsword with leather-wrapped grip" ^
  --category weapon --candidates 4 --keep-candidates
```

정상 출력 순서:

1. `ComfyUI 연결 OK — http://127.0.0.1:8188 (버전 ...)`
2. `[1/4] 큐잉 (seed=...)` → `진행 n/32`
3. 후보별 후처리·QA 줄 (`· candidate_00_00.png → PASS 점수 94.0 (축소 1/16, OK)`)
4. `## 선정: ...` + 항목별 QA
5. `## 변경 파일` 목록

> `--id`의 앞부분이 카테고리와 다르면(`test/` 등) 경고만 찍고 그대로 진행한다.
> 스모크 테스트는 이대로 두고, 확인 뒤 7-4에서 지운다. 실제 에셋은 §10 명명 규칙대로
> `<category>/<snake_case>`를 쓴다.

### 7-3. 박물관에서 확인

```bat
npm start
```

<http://localhost:3000/museum.html> → 무기 홀에서 `style_probe`를 찾는다.
기준 캐릭터와 나란히 놓고 채도·명암·외곽선·픽셀 밀도를 눈으로 비교한다. 밤/비/횃불 버튼도 눌러 본다.

QA 뱃지가 FAIL이면 뷰어에서 어떤 항목이 깨졌는지 본다. 흔한 원인:

- `palette` FAIL → 후처리가 안 걸린 파일을 직접 넣었을 때
- `light` WARNING → 프롬프트에서 광원 문구가 밀렸을 때. `--candidates`를 늘려 다시 뽑는다
- `sizeRatio` WARNING → 정수 배율 제약. `--size`로 캔버스를 조정하거나 재생성

### 7-4. 정리

```bat
python tools\pipeline\register.py --remove test/style_probe
rmdir /s /q public\assets\test
rmdir /s /q tools\pipeline\out\test
```

## 9. 애니메이션 트랙 (`--anim`)

**추가로 설치할 모델·커스텀 노드는 없다.** 정지 컷과 똑같은 SDXL + pixel-art-xl + fp16-fix VAE만 쓴다.
ComfyUI 코어 노드 `LoadImage` · `ImageScale` · `VAEEncode` 세 개가 더 등장할 뿐이다.
§1~3을 이미 끝냈다면 아래 명령이 바로 돈다.

### 9-1. 기본 사용 — 명령 한 줄

```bat
:: 1) 정지 컷을 먼저 만들어 승인한다 (애니의 '원기'가 된다)
python tools\pipeline\generate.py --id monster\wolf --name "늑대" ^
  --desc "grey timber wolf, bared teeth" --category monster

:: 2) 그 정지 컷을 앵커로 걷기 애니를 뽑는다
python tools\pipeline\generate.py --id monster/wolf --name "늑대" ^
  --desc "grey timber wolf, bared teeth" --category monster --anim walk

:: 3) 같은 에셋에 idle을 추가하면 sheet.png에 행이 '쌓인다'
python tools\pipeline\generate.py --id monster/wolf --name "늑대" ^
  --desc "grey timber wolf, bared teeth" --category monster --anim idle

:: 횃불 불꽃 — 정지 컷 없이도 된다(variation 전략)
python tools\pipeline\generate.py --id furniture/torch --name "횃불" ^
  --desc "wall torch with burning flame" --category furniture --anim flicker

:: 마법 이펙트
python tools\pipeline\generate.py --id effect/fire_burst --name "화염 폭발" ^
  --desc "expanding fire burst" --category effect --anim burn --anim-frames 6
```

`--anim`이 붙으면 **정지 생성은 아예 건너뛴다.** 기존 정지 계약(`run_batch.py` 포함)은 그대로다.

### 9-2. 세 가지 전략 (`--anim-strategy`)

| 전략 | 방식 | 언제 쓰나 | 기본 적용 |
|---|---|---|---|
| **anchor** | 승인된 `base.png`에서 출발하는 img2img (`denoise` < 1.0) | 캐릭터·동물·몬스터처럼 **프레임 간 정체성이 생명**일 때 | 대부분의 카테고리 |
| **variation** | 시드만 바꾼 txt2img | 불꽃·마법처럼 아트바이블 §7이 "프레임마다 실루엣 30%+ 변화"를 요구할 때 | `furniture`, `effect` |
| **sheet** | 한 장에 프레임 열을 그리고 **내용 인식 슬라이싱** | 외부에서 만든 시트를 취입하거나 실험할 때 | (기본 아님) |

> **왜 sheet가 기본이 아닌가:** SDXL 한 장(≈1M 픽셀)에 8프레임을 담으면 프레임당 190px 남짓이다.
> 아트바이블이 요구하는 하이비트 밀도(캐릭터 96~112px를 4~8배로 그려 내려찍기)가 나오지 않는다.
> anchor는 프레임마다 1024px을 온전히 쓴다.

> **왜 AnimateDiff를 안 쓰나:** SDXL용 모션 모듈은 2026년에도 beta 품질이고, 시간축 스무딩이
> 픽셀아트의 딱딱한 경계를 뭉갠다. ControlNet OpenPose 경로는 캐릭터마다 Blender/Mixamo 포즈
> 시트를 만들어야 해서 "명령 한 줄"이 성립하지 않는다. 둘 다 커스텀 노드도 여럿 필요하다.

### 9-3. 애니 이름과 기본 프레임 수

아트바이블 §9 표를 그대로 따른다. `--anim-frames`로 언제든 덮어쓸 수 있다.

| 이름 | 캐릭터 | 몬스터 | fps | 루프 |
|---|---|---|---|---|
| `idle` | 6 | 4 | 8 | ○ |
| `walk` (별칭 `move`) | 8 | 6 | 12 | ○ |
| `run` | 8 | 6 | 12 | ○ |
| `attack` | 6 | 6 | 12 | × |
| `gather` / `craft` | 6 | — | 12 | ○ |
| `hit` | 3 | 3 | 15 | × |
| `death` | 8 | 8 | 10 | × |

'움직이는 사물'용으로 §9 표 밖의 이름도 준비돼 있다 (전부 `config.json`의 `anim.frames`로 조정 가능):

| 이름 | 기본 프레임 | fps | 용도 |
|---|---|---|---|
| `flicker` (별칭 `flame`) | 4 | 10 | 횃불·램프 |
| `burn` (별칭 `fire`) | 6 | 12 | 모닥불·화염 |
| `sway` (별칭 `wind`) | 4 | 6 | 식물·나무 흔들림 |
| `cast` | 6 | 12 | 마법 시전 |
| `impact` | 6 | 15 | 타격 이펙트 |

표에 없는 이름을 주면 경고만 내고 시트 맨 뒷행에 붙인다.

### 9-4. 세부 옵션

| 옵션 | 뜻 |
|---|---|
| `--anim-frames N` | 프레임 수 (2 이상) |
| `--anim-strategy` | `anchor` / `variation` / `sheet` |
| `--anim-denoise 0.0~1.0` | anchor 전략의 변형 강도. **낮으면 정체성↑ 움직임↓, 높으면 반대** |
| `--anim-fps N` | 재생 fps 강제 |
| `--seed N` | 프레임마다 `N, N+1, ...`을 쓴다. 재현이 필요할 때 |

`--anim-denoise`가 이 트랙의 핵심 손잡이다. 기본값은 `config.json`의 `anim.denoise`에 애니별로 들어 있다
(`idle` 0.42 → `death` 0.66 → `burn` 0.75). 결과를 보고 이 표를 조정하는 것이 가장 빠른 튜닝이다.

### 9-5. 외부 시트 취입 (내용 인식 슬라이싱 단독 실행)

Aseprite 등으로 만든 시트나 다른 도구의 출력물을 그대로 프레임으로 자를 수 있다.
**균등 그리드로 자르지 않는다** — 알파 점유 프로파일의 빈 골짜기를 찾아 프레임 경계를 잡으므로
프레임 폭·간격이 제각각이어도 팔다리가 잘리지 않는다.

```bat
python tools\pipeline\animslice.py --src my_sheet.png --out tools\pipeline\frames\wolf ^
  --anim walk --category monster --frames 8
python tools\pipeline\spritesheet.py --frames tools\pipeline\frames\wolf --out public\assets\monster\wolf\sheet.png
```

### 9-6. 자동 검사 — 프레임 일관성

애니를 뽑을 때마다 다음을 재서 리포트한다 (등급은 **WARNING까지만**, FAIL은 내지 않는다).

- **실루엣 IoU**: 연속 프레임의 알파 마스크 교집합/합집합
  - 캐릭터: 최소 IoU < 0.45면 "정체성이 흔들린다", 평균 IoU > 0.92면 "움직임이 없다"
  - 이펙트: 평균 IoU > 0.80이면 "§7의 30%+ 변화가 부족하다"
- **색 분포 편차**: 프레임 간 색 히스토그램 L1 거리 평균 > 0.18이면 경고
- **크기 편차**: 콘텐츠 높이 표준편차/평균 > 0.15 (이펙트는 0.45)이면 경고

임계값은 `config.json`의 `anim.consistency`에서 조정한다.

> **박물관과의 차이:** `museum.js`는 정지 이미지 1장만 분석하므로 이 검사를 계산할 수 없다.
> 그래서 애니 에셋은 파이프라인이 WARNING인데 박물관은 PASS로 보일 수 있다. 의도된 차이다.

### 9-7. 시트 누적 규칙

- `sheet.png`는 **가로 = 프레임, 세로 = 애니메이션 행**이고 행 순서는 §9 표 순이다.
- 같은 에셋에 애니를 추가하면 기존 행을 풀었다가 새 행과 함께 다시 굽는다 — **기존 행은 보존된다.**
- 같은 이름으로 다시 뽑으면 그 행만 교체된다(중복 행이 생기지 않는다).
- 프레임 크기가 기존 시트와 다르면 섞지 않고 거절한다. 이때는 `sheet.png`와 `meta.json`의
  `frames`를 지우고 처음부터 다시 만든다.
- `meta.json` / `manifest.json`의 `frames.anims`가 함께 갱신되고, 박물관 뷰어가 이 스키마를 그대로 재생한다.

## 9-8. 배경 잔존 검사와 자동 복구 (`backgroundResidue`)

모델이 마젠타 지시를 무시하고 베이지·회색·올리브 **스튜디오 배경**을 그리는 일이 잦다.
그대로 두면 양자화가 배경을 팔레트색으로 바꿔 놓아 다른 검사에 전혀 안 걸린 채 게시된다.
두 겹으로 막는다.

**1) 후처리 자동 복구** — `remove_key_color`가 전체의 **8% 미만**만 지웠으면 "마젠타 배경이
아니었다"로 보고 폴백을 돈다. 테두리 4변에서 지배 배경색을 통계 내고, 그 색으로 **테두리에서
시작하는 flood fill**을 돌려 배경과 이어진 영역만 지운다. 임계는 테두리 색의 퍼짐에서 뽑고
(비네트·그림자 흡수), 국소 연속성으로 그라데이션을 따라가되 시드색에서 60을 넘게 벗어나면
멈춘다(피사체 침범 방지). **flood fill이라 오브젝트 안쪽의 같은 색 픽셀은 살아남는다.**
발동하면 로그에 남고 후보 줄에 `· 배경폴백`이 붙는다.

**2) QA 반려** — 최종 PNG의 캔버스 테두리 **2px 링** 불투명 비율이 **5%를 넘으면 FAIL**(2% 초과는 WARNING).
- 하단 앵커 카테고리는 **바닥 변을 검사에서 뺀다** — 발이 바닥에 닿는 것은 규격상 정상이기 때문이다.
  (실측: 정상 프로브 `mineral/rock_node`는 바닥 변 포함 시 17%, 제외 시 0%)
- 중앙 앵커(아이콘·초상·이펙트)는 4변 전부 본다.
- 타일(`tileset`)은 배경 제거 대상이 아니므로 SKIP.
- FAIL 후보는 점수가 높아도 **1위로 뽑히지 않는다**(전부 FAIL이면 경고와 함께 최고점을 쓴다).

> `museum.js`는 이 검사를 갖고 있지 않다(정지 1장 분석으로도 가능하지만 아직 미이식).
> 박물관이 PASS인데 파이프라인이 FAIL이면 파이프라인이 옳다.

## 9-9. 규칙이 바뀐 뒤 전수 재검수 (`requalify.py`)

QA 규칙이 늘어나면 예전에 통과한 에셋이 사실은 반려 대상일 수 있다. 전수로 다시 재고, 
**재생성 명령까지 복붙 가능하게** 뽑아 준다.

```bat
:: 전수 재검수 (표 + 집계 + 재생성 명령)
python tools\pipeline\requalify.py

:: FAIL만 보기 / 특정 카테고리만
python tools\pipeline\requalify.py --fail-only
python tools\pipeline\requalify.py --category mineral

:: 재검사 결과를 manifest의 qa 필드에 반영
python tools\pipeline\requalify.py --write
```

출력 끝에 FAIL 에셋이 든 배치 파일을 찾아 이런 명령을 만들어 준다 (배치별 묶음 1줄 + 개별 줄).

```bat
python tools\pipeline\run_batch.py tools\pipeline\batches\batch3_nodes_flora.json --only mineral/oil_seep,mineral/iron_node --force
```

`run_batch.py --only`는 **쉼표로 여러 id**를 받는다.

## 9-10. 타일 심리스화와 심 검사 (`seamScore`)

생성 모델은 프롬프트로 "seamless"를 시켜도 **상하/좌우 랩을 맞춰 주지 않는다.**
실측(최종 64px): `desert` 상하랩 44.5(내부 세로 38.5) · `grass` 55.3(43.3). 게임에서 타일을 깔면
이 차이가 격자 줄무늬로 보인다. 두 겹으로 막는다.

**1) 후처리 자동 심리스화** — 축소해 64px가 된 직후, 가장자리 **7px 대역**을 반대편과
코사인 가중으로 α-블렌드한다(가로·세로 각각). 블렌드 가중치 최대 **0.45** — 0.5로 하면 양 끝 줄이
완전히 같아져 2px 평평한 띠가 보이기 때문에 일부러 조금 남긴다. 블렌드가 만든 팔레트 밖 중간색은
기존 양자화가 다시 스냅한다(**팔레트 순수성 유지**). 리포트의 `seam.before/after`에 수치가 남는다.

실측 개선 (최종본 4종, `score` = 축별 랩/내부 비율의 최댓값):

| 타일 | 전 | 후 | 랩 상하 |
|---|---|---|---|
| `grass` | 1.28 | **0.49** | 55.3 → 16.0 |
| `desert` | 1.50 (WARNING) | **0.45** | 44.5 → 16.8 |
| `snow` | 1.04 | **0.23** | 24.1 → 5.9 |
| `water` | 0.90 | **0.40** | 17.5 → 2.6 |

끄려면 `config.json`에 `"seamless": false`, 대역을 바꾸려면 `"seamBand": 8`.

**2) QA `seamScore`** — 좌↔우·상↔하 랩 차이를 **같은 축의 내부 인접 줄 평균**과 비교한 비율.
축별 비율의 **최댓값**을 쓴다(한 축만 어긋나도 잡아야 하므로). **> 2.0 FAIL · > 1.4 WARNING.**
분모에는 바닥 4.0을 깐다 — 잔잔한 물처럼 매끈한 타일은 내부 차이가 0에 가까워 그대로 나누면
눈에 안 보이는 차이가 무한대 비율이 되기 때문이다. 타일이 아닌 카테고리는 SKIP이고,
FAIL 후보는 랭킹에서 1위가 되지 않는다.

## 9-11. 타일 구도 검사 (`tileComposition`)

타일이 **지면 텍스처가 아니라 "어떤 장소를 그린 그림"으로 나오는** 실패 모드가 있다
(실물: `rock` = 항공 지도, `ash` = 석양+산 풍경화, `desert_b` = 떠 있는 섬 횡스크롤 장면).
반대로 질감이 통째로 사라져 **거의 단색 민무늬**가 되기도 한다(`fertile`, 308바이트).
둘 다 팔레트·심 검사로는 안 잡힌다 — 큰 스케일 구조를 따로 잰다.

**측정 4종** (최종 64px, RGB):
- `block` — 타일을 **4×4 격자**로 나눈 16구획의 평균색 분산(√). 큰 덩어리 구성 = 장면
- `rowVar` / `colVar` — 행평균·열평균의 변동(√). **각각 재서 max를 쓴다**
- `std` — 전 픽셀 채널별 표준편차 합(√). 질감의 총량
- `colors` — 고유색 수

**판정**: 장면성은 `max(행, 열) > 27 FAIL / > 22 WARNING` **또는** `block > 30 FAIL / > 20 WARNING`.
민무늬는 `std < 4.5 FAIL / < 6.0 WARNING` **또는** `colors < 6 FAIL`. 타일 아니면 SKIP.

> **왜 행/열을 따로 재고 max를 쓰나:** `desert_b`는 열(12.4)은 멀쩡하고 행(31.8)만 튄다.
> 평균을 내면 22.1로 희석돼 안 잡힌다.

**보정 근거 (실물 8종 실측)** — 이 표가 임계의 출처이며 `qa.py` 주석에도 그대로 있다.

| 타일 | 4×4격자 | 행평균 | 열평균 | 고유색 | 전체std | 판정 |
|---|---|---|---|---|---|---|
| `grass` | 12.6 | **21.0** | 10.2 | 22 | 11.1 | PASS (경계 — 행 21.0 vs 임계 22.0) |
| `snow` | 10.6 | 11.8 | 11.1 | 16 | 9.1 | PASS |
| `water` | 7.0 | 15.6 | 4.6 | 9 | 7.3 | PASS |
| `desert` | 5.9 | 19.8 | 5.4 | 8 | 8.0 | PASS (구도는 정상, 내용은 벽돌이었음) |
| `rock` | 56.7 | 44.6 | 59.9 | 22 | 12.7 | **FAIL** 풍경 |
| `desert_b` | 16.9 | 31.8 | 12.4 | 22 | 9.5 | **FAIL** 풍경 |
| `ash` | 66.8 | 56.3 | 40.8 | 22 | 12.7 | **FAIL** 풍경 |
| `fertile` | 0.2 | 0.4 | 0.3 | 5 | 2.2 | **FAIL** 민무늬 |

**프롬프트 쪽 방어**: tileset 템플릿에 `(orthographic view pointing straight down at flat ground:1.3)` ·
`(close-up macro texture of the ground itself:1.2)` 가중을 넣고, "the camera looks straight down,
the ground fills the whole frame at one constant distance, not a landscape and not a scene"를 붙인다.
tileset 전용 네거티브에 `landscape, scenery, horizon, sky, sun, moon, clouds, mountains, cliffs,
valley, river, lake, coastline, aerial map, world map, side view, side-scroller level,
isometric scene, diorama, vignette, painting of a place, distant view`가 추가된다.

## 10. 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| `ComfyUI가 응답하지 않습니다` | `run_nvidia_gpu.bat` 실행 여부 → 브라우저 접속 → `config.json`의 `comfyUrl` → 방화벽 순으로 확인 |
| `CheckpointLoaderSimple에 '...' 가 없습니다` | 모델 파일명/폴더가 틀렸다. §2 표와 대조하고 **ComfyUI 재시작** |
| `생성이 900초 안에 끝나지 않았습니다` | ComfyUI 콘솔에 CUDA OOM이 없는지 확인. 있으면 `--lowvram` 또는 `candidates`를 줄인다 |
| `배경을 지우고 나니 남은 픽셀이 없습니다` | 모델이 마젠타 배경을 통째로 그렸다. `--seed`를 바꿔 재생성하거나 `desc`에 주제를 더 구체적으로 |
| 결과에 마젠타 테두리가 남음 | `config.json`의 `haloTolerance`를 190 → 210으로 올린다 |
| 결과가 뭉개져 보임 | `quantizeStrength`를 0.7~1.0으로 올려 색을 더 줄인다. 그래도 안 되면 `--candidates`를 늘려 뽑는다 |
| 콘텐츠가 규격보다 작다는 안내 | 정수 배율(§6)만 허용해서 생기는 구조적 제약이다. 다른 시드를 뽑거나 `--size`로 캔버스를 조정한다 |
| 한글이 `cp949`로 깨짐 | `set PYTHONUTF8=1` 후 실행 (MCP 서버는 이미 자동으로 설정한다) |
| `import websocket` 실패 | `pip uninstall websockets` → `pip install websocket-client` |
| QA `backgroundResidue` FAIL | 모델이 마젠타 대신 다른 배경을 그렸다. 후처리 폴백이 못 지운 경우다. `--seed`를 바꿔 재생성하거나 desc에 배경 언급을 빼라 |
| 로그에 `마젠타 배경이 아닙니다 ... 폴백으로 N% 제거` | 정상 동작이다(자동 복구). 다만 자주 뜨면 프롬프트가 배경 지시를 잃고 있다는 신호다 |
| 오브젝트인데 사람이 나옴 | 해당 카테고리 네거티브에 person 계열이 들어가는지 `--dry-run`으로 확인하고, desc를 "a single ... object, no people"처럼 구체화 |
| 한 장에 아이템이 여러 개(콜라주) | desc에 "one single / as one / one connected" 문구를 넣는다. 네거티브에 collage 계열이 붙는지 `--dry-run`으로 확인 |
| 타일을 깔면 격자 줄무늬가 보임 | 후처리가 자동으로 랩 크로스페이드를 건다(§9-10). 그래도 남으면 `config.json`에 `"seamBand": 8`을 주거나 QA `seamScore` 수치를 확인 |
| QA `seamScore` WARNING/FAIL | 랩 차이가 내부 텍스처 대비 크다. `--seed`를 바꿔 재생성하거나 `seamBand`를 8로 올린다 |
| 지형 타일이 벽돌·포장돌로 나옴 | **`tile`이라는 단어가 세라믹/포장 타일로 읽힌다.** desc에서 "... tile" 대신 "... ground surface"를 쓰고 "no bricks, no masonry, natural ground only"를 붙인다(카테고리 네거티브에도 이미 포함) |
| 타일이 풍경화로 나옴(하늘·산·강·항공지도·횡스크롤 장면) | QA `tileComposition`이 FAIL로 잡는다. desc에서 원경 어휘(`outcrop`, `dune ridge`, `valley`, `plain`)를 빼고 "close-up ground texture at hand scale, camera pointing straight down, no horizon, no sky"를 넣는다. 카테고리 네거티브에 landscape/horizon/sky 계열이 이미 붙는다 |
| 타일이 질감 없는 민무늬로 나옴 | 역시 `tileComposition` FAIL(전체std < 4.5 또는 고유색 < 6). desc에 알갱이·덩어리 디테일과 **two-tone 명암**을 명시하라: "visible clods of many sizes, moist darker clumps beside drier lighter crumbs, never a flat single color" |
| 타일에 꽃·오브젝트가 과밀 | desc의 "two or three" 같은 수량은 잘 안 지켜진다. "at most two ... in the entire frame, no flower field, no dense flowers"처럼 **금지형**으로 쓴다 |
| `앵커로 쓸 정지 컷이 없습니다` | `--anim`은 `base.png`를 원기로 쓴다. 정지 에셋을 먼저 만들거나 `--anim-strategy variation` |
| 애니 경고: `프레임 간 실루엣이 과하게 변합니다` | `--anim-denoise`를 0.1 낮춘다(정체성↑) |
| 애니 경고: `프레임 차이가 거의 없습니다` | `--anim-denoise`를 0.1 올린다(움직임↑) |
| 애니 경고: `이펙트 실루엣 변화가 부족합니다` | variation 전략인지 확인하고 `--anim-denoise`를 0.8까지 올린다 |
| 슬라이싱 프레임 수가 안 맞음 | `--anim-frames N`을 주면 병합/분할로 강제로 맞춘다 |
| `기존 시트의 프레임 크기 ...가 다릅니다` | `sheet.png`와 `meta.json`의 `frames`를 지우고 처음부터 다시 만든다 |

## 11. 파이프라인이 하는 일 (요약)

```
프롬프트 조립  아트바이블 §1~7(하이비트·좌상단 45° 광원·팔레트 hex·1px 잉크 외곽선·3/4 탑다운)
   ↓          + 카테고리 템플릿 + 사용자 --desc(영문) + 마젠타 단색 배경 강제
ComfyUI       SDXL 1024px, 시드를 바꿔 후보 N장 (websocket으로 진행률 수신)
   ↓
후처리        마젠타 제거(RGB 거리) → halo 1px씩 절삭 → 알파 0/255 이진화 → 고립 픽셀 제거
   ↓          → 콘텐츠 트림 → **정수 배율 nearest 축소** → 마스터 팔레트 양자화(색 예산 16~28)
   ↓          → 하단 중앙(또는 중앙) 앵커 배치
QA            §11 9개 항목 채점 → 후보 자동 랭킹 → 1위를 base.png
등록          meta.json 작성 + manifest.json 원자적 갱신(scale/offset 보존, id 정렬)

--anim 트랙   전략 분기(anchor=base.png img2img / variation=시드만 교체 / sheet=1장+슬라이싱)
   ↓          → 프레임별 위상 프롬프트(contact·passing·up·down 등)
슬라이스/정렬  내용 인식 슬라이싱(알파 점유 골짜기) → **전 프레임 공통 배율 1개** → 공통 캔버스
   ↓          → 하단 중앙 앵커(시트 출신은 발 높이 상대차 보존)
시트 병합     기존 행 보존하며 §9 순서로 다시 굽기 → frames.anims 갱신
일관성 검사   실루엣 IoU·색 분포·크기 편차 → WARNING 리포트
```

> **QA 규칙 이중화 주의:** `tools/pipeline/qa.py`의 `THRESHOLDS` · `CATEGORY_SPEC` ·
> `ANIM_FRAMES_*` 는 `public/js/museum.js`의 동명 상수를 1:1로 옮긴 것이다.
> 알고리즘 세부(불투명 기준 알파 250, 그리드 추정 런 길이 상한 16 및 80% 정합, 외곽선 허용색
> 거리 10, 상/하 luma를 **콘텐츠 bbox 중앙**으로 가르는 것)까지 같다.
> **한쪽을 고치면 반드시 다른 쪽도 같이 고칠 것.** 안 그러면 파이프라인과 박물관 판정이 갈린다.

git은 건드리지 않는다. 스테이징은 사람이 결정한다.
