# AI 활용 기술 문서 — 갈래말래 (가제)

최종 수정: 2026-08-04 (AI 자동 최신화 — v3.0 엔드리스 전환 + QA 마감 반영)

## 1. 개발 공정에서의 AI 활용

### 1-1. 역할 분담 파이프라인
```
이성효 (기획서 v6.0 + 유물 문서 → GDD v3 지시, Notion)
  └→ Claude Fable 5  : 기획 통합 분석 → 모순 발견·구현 결정(D1~D12) → SPEC.md + PROTOCOL.md 작성
        ├→ Opus 에이전트 A (서버) ─┐  프로토콜 계약만 공유하고 완전 병렬 개발
        ├→ Opus 에이전트 B (클라) ─┘
        └→ Opus 에이전트 C (통합·QA) : 쟁점 해소, E2E, 밸런스 튜닝, 실브라우저 스모크
```
- **계약 우선 병렬화**: 서버·클라가 서로의 코드를 모르는 채 PROTOCOL.md만 보고 동시 개발 → 통합 에이전트가 쟁점을 일괄 해소. 에이전트 3기 병렬+직렬 조합
- **검증 강제**: 각 에이전트에 "밸런스 문서의 표 값을 테스트로 재현하라"를 요구 — 기획서 수치(드래곤 R=1.14→66%, 무역 배수 1.17/1.46/2.25 등)가 **테스트 123개**로 고정됨
- **모순 검출**: AI가 기획서 간 수학적 충돌 4건(시간 모델, 연료 소비, 감정의 날 조건, 평시 방어 노동)을 계산으로 발견 → QUESTIONS.md로 기획자에게 회부
- **계약 불일치 검출(v3.0 QA)**: 자료 파일끼리의 어긋남도 테스트로 못 박았다 —
  `skills.defs[*].nodeTypes` 에 있는데 `skills.nodes` 에 규격이 없던 `water`(물가)가 그렇게 잡혔고,
  이제 `test/fishing.test.js` 가 "스킬이 맡는 노드는 전부 스윙 규격이 있다"를 매번 검사한다

### 1-3. AI 가 스스로 잡은 사고 (v3.0 QA 세션)
사람이 리포트하지 않았는데 **검증 도구가 먼저 찾아낸** 것들이다 — 도구를 정확하게 만드는 일 자체가 AI 활용의 핵심이었다.

| 사고 | 어떻게 드러났나 | 정공 해법 |
|---|---|---|
| 도끼질을 해도 자원칸이 최대 10분 묵는다 | 안개 수정으로 `lordMove` 의 상태 전량 방송을 걷어내자 곧바로 하니스가 실패 — **우연히 가려져 있던 사고**였다 | 실시간 ack 에 창고 잔고(권위값)를 실어 화면 장부에 즉시 반영 |
| 토스트가 컷신 [건너뛰기] 단추를 덮어 못 누른다 | 실브라우저 스모크의 **진짜 마우스 클릭**이 안 먹혀서 `elementFromPoint` 로 추적 | 시간이 정해진 단추를 알림 위로 + 컷신 중 알림 더미를 비켜 세움 |
| 성능 게이트가 통과 불가능한 조건이었다 | 「평균 프레임 시간 < 16ms」가 늘 16.67ms — 재는 값이 **프레임 간격**이었다 | 그리는 데 든 시간(0.27ms)과 간격(16.67ms)을 나눠 재도록 지표 재정의 |
| 하니스·스모크가 매번 다른 땅을 받아 간헐 실패 | 물가가 없는 지도·울타리 자리가 물인 지도에서만 실패 | `?seed=` 손잡이를 두고 검사에서 **씨앗 고정** |

### 1-2. 사용 프롬프트 요지 (재현용)
- 서버: "SPEC·PROTOCOL·기획서를 읽고 순수 함수 엔진 구현. 매직넘버 금지, 표 값 재현 테스트 필수, public/ 금지"
- 클라: "PROTOCOL의 이벤트만 사용, mock은 NationView와 한 글자도 다르지 않게, CDN 금지"
- 통합: "쟁점별 결정을 지시(위임하지 않음), 계약 변경 시 문서 동시 갱신, E2E로 풀시즌 통과"

## 2. 게임 내 AI 시스템 — 3계층 (기획 §10 그대로 구현)

| 계층 | 구현 | LLM |
|---|---|---|
| 판단 | server/engine/ — NPC 정책 봇, 섭정(오프라인 ×0.7 + 결정 큐), AI 3국 무역 봇 | 안 씀 |
| 표현 | server/expression/ — 사실 JSON → 한국어 문장. 템플릿 18종×3~5변형 기본, ANTHROPIC_API_KEY 있으면 Claude 호출(5초 타임아웃 → 템플릿 폴백, 비동기 큐라 게임 진행 비차단) | 선택 |
| 검증 | server/sim/ — 무접속 시뮬 20회 × 85게임일, 체크포인트 **4항목**(티어3 도달일·웨이브5 생존율·식량 파산율·성녀 격차) | 안 씀 |

- LLM 금지 규칙 준수: 수치 연산(생산량·가격·전투)에 LLM 불개입. 입력은 판단 결과 스냅샷 JSON만, 출력은 표시 텍스트만
- 소비처: 성녀 예언 대사, NPC 어전 회의 보고, 치세 보고서, 이벤트 서사, 유물 발견 서사

## 3. 도구 내역
| 도구 | 용도 |
|---|---|
| Claude Cowork (Fable 5) | 기획 분석·설계·오케스트레이션·문서화 |
| Claude Opus (서브에이전트 ×3) | 서버/클라/통합 코드 작성 |
| Node 22 + node:test | 단위·E2E 테스트 **123개** (`npm test`) |
| jsdom | 브라우저 없는 클라이언트 하니스 **20항목** — 실서버에 붙어 개척→웨이브 완주 (`npm run harness`) |
| 헤드리스 크롬 + CDP | **실브라우저 연기 검사 56항목** — 진짜 마우스·키보드로 첫 30분 시나리오 완주 + 프레임 측정 (`npm run smoke`, 의존성 추가 없이 Node 내장 WebSocket 으로 개발자 도구 규약에 직접 말을 건다) |
| 자체 시뮬레이터 | 밸런스 검증 20회 × 85게임일, 체크포인트 4/4 (시드 고정 재현성, `npm run simulate`) |
| 정적 검사 | 화면 규칙·금지어·폐기 명령·규약 판번호 (`npm run check:ui`) |
