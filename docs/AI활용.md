# AI 활용 기술 문서 — 갈래말래 (가제)

최종 수정: 2026-08-06 (AI 자동 최신화 — §17-19 표현·타격감/대화창까지 반영)

## 1. 개발 공정에서의 AI 활용

### 1-1. 역할 분담 파이프라인
```
이성효 (기획서 v6.0 + 유물 문서 → GDD v3 지시, Notion)
  └→ Claude Fable 5  : 기획 통합 분석 → 모순 발견·구현 결정(D1~D12) → SPEC.md + PROTOCOL.md 작성
        ├→ Opus 에이전트 A (서버) ─┐  프로토콜 계약만 공유하고 완전 병렬 개발
        ├→ Opus 에이전트 B (클라) ─┘
        └→ Opus 에이전트 C (통합·QA) : 쟁점 해소, E2E, 밸런스 튜닝, 실브라우저 스모크
```
- **계약 우선 병렬화**: 서버·클라가 서로의 코드를 모르는 채 PROTOCOL.md만 보고 동시 개발 → 통합 에이전트가 쟁점을 일괄 해소. 에이전트 3기 병렬+직렬 조합
- **검증 강제**: 각 에이전트에 "밸런스 문서의 표 값을 테스트로 재현하라"를 요구 — 기획서 수치(드래곤 R=1.14→66%, 무역 배수 1.17/1.46/2.25 등)가 **테스트 123개**로 고정됨
- **모순 검출**: AI가 기획서 간 수학적 충돌 4건(시간 모델, 연료 소비, 감정의 날 조건, 평시 방어 노동)을 계산으로 발견 → QUESTIONS.md로 기획자에게 회부
- **계약 불일치 검출(v3.0 QA)**: 자료 파일끼리의 어긋남도 테스트로 못 박았다 —
  `skills.defs[*].nodeTypes` 에 있는데 `skills.nodes` 에 규격이 없던 `water`(물가)가 그렇게 잡혔고,
  이제 `test/fishing.test.js` 가 "스킬이 맡는 노드는 전부 스윙 규격이 있다"를 매번 검사한다

### 1-3. AI 가 스스로 잡은 사고 (v3.0 QA 세션)
사람이 리포트하지 않았는데 **검증 도구가 먼저 찾아낸** 것들이다 — 도구를 정확하게 만드는 일 자체가 AI 활용의 핵심이었다.

| 사고 | 어떻게 드러났나 | 정공 해법 |
|---|---|---|
| 도끼질을 해도 자원칸이 최대 10분 묵는다 | 안개 수정으로 `lordMove` 의 상태 전량 방송을 걷어내자 곧바로 하니스가 실패 — **우연히 가려져 있던 사고**였다 | 실시간 ack 에 창고 잔고(권위값)를 실어 화면 장부에 즉시 반영 |
| 토스트가 컷신 [건너뛰기] 단추를 덮어 못 누른다 | 실브라우저 스모크의 **진짜 마우스 클릭**이 안 먹혀서 `elementFromPoint` 로 추적 | 시간이 정해진 단추를 알림 위로 + 컷신 중 알림 더미를 비켜 세움 |
| 성능 게이트가 통과 불가능한 조건이었다 | 「평균 프레임 시간 < 16ms」가 늘 16.67ms — 재는 값이 **프레임 간격**이었다 | 그리는 데 든 시간(0.27ms)과 간격(16.67ms)을 나눠 재도록 지표 재정의 |
| 하니스·스모크가 매번 다른 땅을 받아 간헐 실패 | 물가가 없는 지도·울타리 자리가 물인 지도에서만 실패 | `?seed=` 손잡이를 두고 검사에서 **씨앗 고정** |

### 1-4. 세션 인수인계 파이프라인 (2026-08-06~, 계정 이전 후)

- 배치 C(§17-18): 「감정의 날에 감정되는 요소가 너무 적다」는 피드백에 대해 Opus 에이전트가 **먼저 태그 효과 키의 소비처를 전수 grep** 해 `output`·`gather` 둘만 살아 있고 `defenseTotal`·`populationGrowth`·`unlock` 은 아무도 읽지 않는 죽은 키임을 확인한 뒤, 살아 있는 키 안에서만 새 태그 2종을 설계. 전 태그에 한 줄 이야기(flavor)를 붙이고 컷신을 「5 + 태그 수 + 1」장으로 늘림. 테스트 352/352

- 배치 D(§17-19): 「표현·타격감」은 수치로 못 박기 어려운 영역이라 **에이전트에게 자료 다이얼부터 만들게 했다** — 흔들림 세기·붉은 섬광 농도·스프라이트 배율·타자 속도까지 전부 `data/world.json render.*` 로 빼고 코드에는 한 숫자도 남기지 않았다(「손맛이 약하다」는 피드백이 오면 코드가 아니라 표 한 줄을 만진다). 착수 전 감사에서 **건물 확대의 진짜 위험**을 먼저 찾아냈다: 그림(`world.drawStructures`)과 클릭 판정(`input.structureAtSprite`)이 같은 사각형 식을 각자 베껴 쓰고 있어, 키우는 순간 「보이는데 눌러지지 않는 건물」이 생긴다 → 식을 `world.structureRect` 한 곳으로 합치고 그 동치성을 테스트로 못 박은 뒤에 확대했다. 대화창(D-5)은 외부 그림 파일 없이 atlas 절차 도트를 키워 초상으로 썼다(에셋 0장 원칙 유지). 회귀는 「눈으로 봐야 아는 것」을 뺀 나머지 — 사각형 동치·대화창 규칙 9종을 새로 붙였다
