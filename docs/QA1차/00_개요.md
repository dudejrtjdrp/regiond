# QA 1차 — 분류·우선순위·배치 계획 (2026-08-06)

멀티플레이 QA(방장+초대 유저+봇)에서 나온 피드백 전체를 버그(B)/기능(F)으로 분리해
01~10 카테고리 파일로 정리했다. ID 규칙: `B01-1` = 01 카테고리 버그 1번.

## 대원칙 (모든 배치 공통)
1. 한 번에 다 고치지 않는다 — 아래 배치 순서대로, 배치마다 유저 확인.
2. 기존 기능·저장 데이터·멀티 프로토콜 호환 유지. 계약 변경 시 `docs/PROTOCOL.md` 먼저.
3. 확신 없으면 임의 구현 금지 — 현재 구조 분석 → 최소 변경 리팩토링.
4. 배치마다: 구조 분석 → 구현 → `npm test` 전체 → 상세 커밋 → `docs/AI활용.md` 갱신.
5. 수치는 전부 `data/*.json` — 매직넘버 금지. 밸런스 변경 시 `npm run simulate` 4/4 유지.

## 핵심 가설 ★
01의 버그 대부분은 **「방을 나갔다 같은 코드로 재입장하면 해결」**된다.
→ join 시 풀스냅샷 경로는 정상이고, 이후 **증분 브로드캐스트가 방 전체(io.to(room))가 아니라
방장 소켓(socket.emit)에만 가거나, 게스트가 룸 구독에서 빠져 있는** 계열의 근본 원인일 가능성이 높다.
개별 증상을 하나씩 패치하지 말고 **emit 경로 전수 감사부터** 한다. (01 파일 참조)
